## 확인 못 한 것

- **실제 소리.** 음성은 가짜로 바꿔 '무엇을 언제 읽히고 끊는지'만 봤다. 아이폰에서 한 글자 발음이 끊기는 문제, 실제 읽는 속도(B11이 몇 글자부터 끊기는지), は·へ 한 글자를 음성이 어떻게 읽는지는 보지 못했다.
- **실제 기기와 실제 자판.** 헤드리스 Chromium(리눅스)에서만 했다. iOS Safari, 안드로이드, 한글 자판의 조합 동작, 일본어 자판의 변환은 이벤트를 흉내 냈을 뿐이다. 화면 키보드가 올라온 상태의 배치도 못 봤다.
- **글꼴.** 이 기계의 일본어 글꼴은 IPAGothic, 한글은 대체 글꼴이다. 글자 폭에 달린 결과(B14의 6글자 단어)는 기기에서 조금 다를 수 있다. 획순 그림(B06)은 SVG 고정 폭이라 같다.
- **뒤로 가기로 되살아난 페이지.** 게임 → ⌂ → 합치기 → 뒤로 가기에서 이 브라우저는 페이지를 새로 읽어 기록이 남았다. 모바일 Safari·Chrome이 페이지를 되살리면(bfcache) B02와 같은 일이 생길 수 있는데 재현하지 못했다.
- **저장 실패가 실제로 얼마나 생기는지**(B08은 setItem이 예외를 내게 바꿔 놓고 본 것).
- **내용.** 뜻·해설·발음 설명이 맞는지는 범위 밖이라 보지 않았다.

## 재현 방법

저장소 맨 위에서 돌린다. 모두 읽기만 하고 결과는 이 폴더의 `out/`·`shots/`에 쓴다.

```
node reviews/aesop-20261112/behavior/01-input-sim.cjs            # 1. 전 카드 입력·판정 (25초) → out/input-*.json
python3 reviews/aesop-20261112/behavior/01b-summarize.py         #    통과 못 한 카드·틀렸는데 통과한 입력 목록 (--full이면 전부)
node reviews/aesop-20261112/behavior/02-bruteforce-kana.cjs      # 1. 五十音 글자 카드 × 한글 11,172음절·로마자 (2분 반) → out/bruteforce-kana.tsv
node reviews/aesop-20261112/behavior/09-kana-reveal-vs-input.cjs # 1. 五十音: 공개 칸의 소리를 그대로 치면? ん 끝 처리
node reviews/aesop-20261112/behavior/03-flow.cjs                 # 2. 판 흐름·저장 키·기록 옮기기 (2분) → out/flow.json
node reviews/aesop-20261112/behavior/08-record-loss.cjs          # 2. 기록이 사라지는 길 → out/record-loss.json
node reviews/aesop-20261112/behavior/05-layout.cjs               # 3. 화면 (7분) → out/layout.json, shots/
node reviews/aesop-20261112/behavior/04-speech.cjs               # 4. 발음 경로 → out/speech.json
node reviews/aesop-20261112/behavior/06-extra.cjs                # 흉내 도구 대조, Enter가 필요한 카드 수, 힌트, 제목 잘림, 전 과정 완료
node reviews/aesop-20261112/behavior/07-screens.cjs              # 홈·기록 옮기기 창 그림
```

- `FAIL`은 앱이 기대와 다르게 움직였다는 뜻이고, 어느 지적인지는 review.json의 `repro`에 적었다. `info`는 판정 없이 적어 둔 값이다.
